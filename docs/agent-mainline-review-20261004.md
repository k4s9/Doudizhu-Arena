## 实验设计与结论边界

现有 `shared-first-response-v1` 每个局面只生成一次共同首答，失败后分别进入两条最多两次的重试分支；物理上限是 `1 + 2 + 2 = 5`，每条协议的逻辑上限为三次。它估计固定局面和共同首答条件下，具体规则反馈的增量价值。原计划的三协议各自生成首答，上限 `1 + 3 + 3 = 7`，属于另一种实验，不能混用分母、预算或把共享首答的三组当成独立样本。

历史 Minimax 观察差为 +2.98 个百分点，95% 区间为 −1.19～6.55，不能声称稳定提升；响应模型别名混合也限制归因。Qwen 发现输出 token 超过请求上限，原归档保持审计失败，不通过重写规格或补跑单个样本改成成功。新实现和新报告不能冒充当时的源码或逐字节复核结果。

## 实现与验收记录

本轮实现：

1. **调用证据与进程恢复。** `LoggingLLMProvider` 在进入 Provider 之前，把调用意图、原始 Prompt、预算预留及关联原子保存；返回后更新同一条记录并原子结算。进程中断后，旧 attempt、未完成桌局和调用被明确标记为中断，未知 usage/费用保持未知，预算继续占额；已完成任务不重跑。中断的调用意图不能证明供应商已经接收或计费，系统保守保留占额。
2. **固定观察执行边界。** 免费单价也检查输入/输出 token 上限，超额保存当次证据后停止后续调用；真实模式拒绝注入测试 Provider。共享首答、重试上限和历史计量方式保持不变。
3. **响应身份与源码诊断。** 报告展示名称/指纹覆盖率和配对分组，缺失名称不会被算作一致版本；指纹全部缺失只标为名称证据。分组是运行后形成的描述性子集，总体区间限定于请求别名/端点的实际返回组合。源码核验明确区分一致、不一致、未检查。
4. **语料与来源。** 语料验证拒绝未知或跨组来源、重复时间桶、额外隐藏/未来字段及观察与来源身份不一致。`prepare --seed-namespace` 可以显式生成新 seed；默认旧 seed 不变，生成操作不自动证明数据未经开发使用。
