# 固定局面规则反馈效果实验（2026-09-26）

**真实运行和归档已完成，共 490 次物理调用、384 个模型—局面组合。Minimax 主实验审计通过，观察到 +2.98 个百分点的出牌成功率差，但 95% 区间跨零；Qwen 复核发现输出 token 上限异常，保留为协议审计未通过。** 本轮不能据此声称规则反馈有稳定提升。

本轮检验的问题是：在同一个局面、同一次首答和相同最大调用次数下，具体规则错误反馈相对通用重试，能否提高模型决策成功率，以及增加多少 token 与调用耗时。Minimax 为主实验，Qwen 为描述性复核。它衡量可执行性，不衡量牌力或胜率。两模型都使用同一批 24 个来源测试种子，不能将其计作 48 个独立来源种子。

## Minimax 完整结果

192 个局面全部完成，292 次物理调用，usage 覆盖 292/292；原始报告和独立只读重建均通过审计。

| 出牌协议 | 模型成功 | 成功率 | 首答非法后的恢复 | 逻辑调用 | 平均调用耗时合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单次生成 | 131/168 | 77.98% | 0/37 | 168 | 11.135 秒 |
| 通用重试 | 160/168 | 95.24% | 29/37 | 218 | 14.241 秒 |
| 规则反馈 | 165/168 | 98.21% | 34/37 | 216 | 14.271 秒 |

规则反馈相对通用重试的出牌成功率差为 **+2.98 个百分点，95% 区间 −1.19～6.55**，仍跨过零。观察到 7 个仅反馈成功、2 个仅通用重试成功的局面；另有 158 个两组均成功、1 个均失败。当前证据不足以断言稳定的反馈增益；与单次生成相比的大幅提高也不能全部归因于具体反馈，因为尝试次数同时增加了。

两种重试的出牌总 token 几乎相同：通用重试 412,360，规则反馈 412,331；反馈平均每个出牌局面少 0.17 token，多约 30 毫秒调用耗时。这些极小差异只作本次样本描述，不支持性能或成本优势结论。

实际返回名为 `minimax-m27-eic` 154 次、`minimax-m27` 138 次，没有 system fingerprint。两条分支及首答都只有同一返回名的 135 个出牌局面，描述性成功率差为 0；这个子集按运行后信息筛选，不能当成无偏的替代效果估计，但进一步限制了“反馈本身稳定提升”的解释。[全部 9 个差异案例](reviews/20260926-fixed-effects/minimax/discordant-cases.json)包含反馈胜出和通用重试胜出两个方向。

## Qwen 描述性结果与协议异常

192 个局面全部执行完毕，198 次物理调用，usage 已知 197/198。出牌结果为单次生成 165/168、通用重试 168/168、规则反馈 168/168；两种重试均恢复 2 次首答非法和 1 次首答供应商超时。叫分三组均为 24/24。

一次共享首答的调用 `6611e393654046e7ad6ed30895b476a1`，请求 `max_tokens=8192`，但供应商报告 `completion_tokens=9142`、输入 1260、总计 10402。该首答被两种重试协议共同引用，不能选择性替换或从主分母移除它。现有证据无法判断是网关的上限语义、计量口径还是执行行为导致不一致。

另一次首答 `f7b75a6e4bd74167a2644b91ec5dee8a` 在约 180.25 秒报 `stream timeout`，usage 保持未知，两种分支随后均恢复。这不是已知零 token。

因此 [Qwen 审计](reviews/20260926-fixed-effects/qwen/report/integrity.json)保留 `complete=false`、`issues=["output allowance"]`，不生成主效果区间；原始运行及独立复核均返回非零。表面上两种重试成功数相同，只能作本批异常运行的描述，不能写成协议验证通过或证明等价。没有通过扩大上限、修改 manifest 或重新调用单个样本将其改成成功结果。

197 次返回均报告 `Qwen3.5-397B-A17B`，没有 system fingerprint。已知实际输入/输出 token 为 242,708 / 279,608；Minimax 为 344,269 / 196,448。两模型合计 usage 已知 489/490，价格仍按此前确认的免费账户记录。

## 开跑前冻结的设计

- 从独立的确定性规则策略生成 28 个来源种子的合法完整轨迹，4 个开发种子、24 个留出测试种子，按来源整盘隔离。开发阶段只用 mock 验证管线，不依据测试模型响应修改提示词或抽样。
- 每个种子固定抽取 1 个叫分、3 个领出、4 个跟牌局面；各类别按轨迹时间分箱后抽样，覆盖早期至后期。测试集共 192 个局面，其中出牌 168 个。模型没有参与生成或筛选局面，也没有在真实调用中注入错误。
- 两模型接收相同的冻结局面和提示词。局面只含当前玩家手牌及公开信息；完整来源动作另存，用于重放核验，不发送给模型。
- 每个局面只调用一次共同首答，作为单次生成基线。首答失败后分别分支为“通用重试”和“规则反馈”，每组最多再调用两次，成功即止。只在结构/规则校验失败时提供具体错误；供应商错误在两组均使用相同通用重试提示。
- 每轮两分支的先后次序按预设随机种子打散，局面顺序同样固定随机化。没有根据中途结果提前停止、追加样本或挑选成功案例作为主分母。
- 沿用 `minimax-m27`、`qwen3.5`、Uni API 端点、temperature=0、top_p=1、max_tokens=8192，不传采样 seed。每次调用最多 300 秒；每协议最多 600 秒的自身累计调用时间。两模型各最多 2 个并发请求，合计最多 4 个。
- 每模型物理调用上限为 `192 × (1 + 2 + 2) = 960`。三协议的首答是同一次真实请求，不重复计入实际账本；协议成本比较各自计入首答，不能将三组逻辑消耗相加当成实际费用。
- 价格沿用用户 09-24 确认的免费账户信息，来源与生效日期保留在规格中。记录所有已知 token，未知 usage 保留未知；零美元不是供应商账单核验结论。

测试集 corpus SHA-256（含开发集与来源轨迹）：`bd7a44ef459750554a4a3f5929ed3785be79de56e535e1431ac225eb02039bb5`。

96 个跟牌局面的目标牌型为：单张 80、对子 6、三带一 3，其余三条、三带二、顺子、连对、炸弹、火箭合计 7。这个预设规则策略样本偏向简单牌型，不代表真实玩家局面分布或完整复杂牌型覆盖。

## 指标与解释

主指标为测试集出牌决策的模型成功率差（规则反馈减通用重试，百分点）。按 24 个来源种子做配对簇 bootstrap，固定 20,000 次重采样并报告 95% 区间；先在每个种子内计算差，再给种子等权。叫分、总体结果以及 Qwen 的复核为描述性结果，不作多项联合显著性声明。

同时报告首答非法后的恢复数/分母、供应商错误恢复、每协议实际使用的逻辑调用、已知输入/输出 token、usage 覆盖率及调用耗时合计。耗时指标排除排队及两个分支互相等待的时间，是独立执行各协议时的调用耗时估计，不能写成在线对局端到端延迟。

共享首答有意控制了初始生成差异，因此不能将三组当成独立样本。区间只覆盖这个来源种子样本的不确定性，不覆盖所有供应商时间和模型版本变化。若差异为零导致 bootstrap 区间退化，也不能据此证明两方案等价。

冻结的是请求的模型别名，同时保留每次实际返回的模型名和 system fingerprint。别名若对应多个返回名，结论限定为该端点在运行窗口内的表现；同一返回名也不能证明权重版本完全一致。

## 实现与验证

`fixed_corpus.py` 复用游戏状态机和正式提示词构造器；`fixed_study.py` 复用 `BudgetLedger`、`LoggingLLMProvider` 和 `ExecutionScope`，使用独立数据库。每次物理调用只产生一份响应证据及预算结算，分支引用同一首答的调用 ID。超时或取消到期后禁止迟到结果写入，保留未知 usage。

`fixed_report.py` 从原始响应重新解析结果，核对冻结提示、重试协议、首答引用、调用顺序、样本覆盖、源码和预算关联；主报告不依赖存储的“成功”标签。来源重放和判定器复用项目规则引擎，不属于独立第三方规则验证。

运行入口是 `scripts/fixed_effect_study.py`，必须使用 `doudizhu-arena` conda Python。所有输出目录须为新目录：

```bash
conda run -n doudizhu-arena python -I -B scripts/fixed_effect_study.py prepare \
  --output data/fixed-plan-new

conda run -n doudizhu-arena python -I -B scripts/fixed_effect_study.py run \
  --plan data/fixed-plan-new --output data/fixed-mock-new --split development --mock

# 下列命令会调用两个真实模型，最大 960 次/模型。
conda run -n doudizhu-arena python -I -B scripts/fixed_effect_study.py run \
  --plan data/fixed-plan-new --output data/fixed-real-new --real

# 只读复核新运行；必须使用该运行冻结的同一份源码。
# 2026-09-26 历史公开归档请使用上方 reproduce_fixed_effects.py。
conda run -n doudizhu-arena python -I -B scripts/fixed_effect_study.py audit \
  --run-dir data/fixed-real-new/minimax --output data/fixed-audit-new
```

本轮冻结计划位于 `data/effect-study-20260926/plan/`；运行数据保存在同级独立目录。数据库含本机加密凭据，不进入公开证据归档。

开发阶段验证：104 项相关规则、牌型、解析与可靠性回归通过；14 项实验专项测试通过，另 1 项公开归档凭据检查通过，均未尝试外部连接。专项覆盖首答共享与物理调用计数、错误提示控制、预算停止、取消后的迟到写入、未知 usage，以及响应/提示/标签/模型/账本/首答引用损坏检测。

发现真实输出超限后，另补 1 项回归：即使按免费账户计价为零，输出超限也必须保留审计失败且不生成效果区间。该用例通过；合计 16 项新增专项验证，连同相关回归共覆盖 120 个不同测试用例。

4 个开发种子的两模型 mock 流程各完成 32 个局面、116 次合成调用，审计通过。其合成反馈收益仅用于检验统计管线，不作为真实效果证据。首次组合回归发现 2 项因元组落库为 JSON 数组而误报的审计测试失败，修正为规范化内容比较后，14 项专项复测通过；原始失败日志保留。

归档工具 `scripts/archive_fixed_effects.py` 从只读原库建立新的精简数据库，API Key 从未被复制到目标库；只保留关联选手和实验所需记录。它从公开数据库独立重建所有报告并与原报告逐字节比较，开发集验证已通过。这样可以公开原始响应、物理账本及可离线审计数据库，而不公开私有运行库。
