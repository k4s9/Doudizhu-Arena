# P3：按需调用的纯算法工具（2026-10-03）

已实现 `compare_hand_plans` 与 `analyze_threat`，并接入 OpenAI/Claude 原生工具调用。两个工具只执行本地确定性算法，不调用 LLM、数据库或网络。创建比赛时可勾选“启用出牌分析工具”，默认关闭。详细接口、实测性能及面试讲述见 [设计与面试说明](agent-tools-design-and-interview.md)。

| 能力 | 当前安排 | 理由 |
| --- | --- | --- |
| `compare_hand_plans` | 已实现：比较 1–3 种自选出法，返回剩牌分组与最优性上下界 | 模型决定候选和保炸弹约束，程序做组合搜索 |
| `analyze_threat` | 已实现：检验某玩家可能压过目标或一手走完 | 模型选择问题，程序检验公开信息下的可行性 |
| 合法牌型生成 | 已实现为两工具共用的内部服务，覆盖全部 15 种正式牌型 | 无需单独暴露一个取上下文的工具 |
| 动作校验 | 保留流程中强制执行 | 合法性不依赖模型主动调用 |
| 基础手牌统计、记牌摘要 | 可作为未来自动上下文增强；本次未新增独立工具 | 便宜、常用、参数固定 |
| 案例检索 | 暂缓 | 当前完整记忆已注入，先建立可追溯案例库 |
| 候选动作推演 | 暂缓 | 需要可靠对手策略和隐藏牌分布模型 |

## 已实现的边界

- 执行器创建当前牌手的公开观察快照，移除其他玩家出牌花色、反思时全员手牌及比赛 ID。模型不能传入对手手牌、seed、SQL 或任意搜索预算。
- 点数向量消除花色重复，牌型模板经正式规则复验。拆牌结果提供实际自家牌，威胁证据只提供标为假设的点数。
- 每次决策新建注册表和缓存，结果附 `state_hash`；最终仍提交实际牌并经过引擎校验，不提供跨回合候选 ID 执行接口。
- `generate_turn()` 提供原生 tool-call/result 契约；旧 `generate()` 继续用于关闭工具的比赛、叫分和反思。当前不需要 MCP 服务。
- 每次决策最多 2 次工具调用；拆牌每次最多 3 个候选，参数最多 4,096 字符，结果最多 8,000 字符。每次算法最多 20,000 个搜索节点，拆牌时间预算 90 ms，威胁预算 80 ms。
- 节点和时间双预算协作式中止；拆牌返回可用分组和上下界，未完成威胁搜索返回 `unknown`。这些是本地计算预算，不是硬实时保证。
- 总模型调用仍最多 `retry_limit + 1`（默认 4），工具消耗其中的轮次，最后一轮禁止新增工具调用。整次决策仍受原牌桌超时控制。
- `agent_tool_calls` 保存调用关联、版本、状态与参数/结果哈希、耗时、输出大小和搜索元数据；模型轮次经原日志和可选预算账本记录。后台计算不持有数据库，取消后不会迟到写入或执行出牌。
- 修复正式规则中飞机带翼可能忽略多余牌的问题，并提升规则版本到 `duplicate-four-seat-v3-complete-airplane`；历史冻结实验不得直接当作同规则结果继续运行。

## 怎么验证值得加入

已经验证算法正确性、原生协议与毫秒级计算性能；[1900 次离线基准](reviews/20261003-agent-tools/benchmark.json)不包含真实模型，也不证明策略提升。下一步应冻结同一批局面，比较三组：关闭分析；程序按固定规则自动触发同一分析；模型按需调用。后两组区分计算能力的收益与自主选择调用的收益。

模型版本、初始经验、局面、最大输出 token、总模型调用次数和总费用上限一致。工具调用占用相同决策时间预算，不能额外赠送模型重试次数。工具结果长度计入后续提示词，单列工具计算耗时与模型等待耗时。

报告首答合法率、最终合法率、重试与兜底率、工具调用率、拒绝/超时率、输入输出 token、已知费用与未知费用占额，以及总延迟的中位数和 P95。先按独立 seed 做配对比较，再对冻结配置做完整 AB 对战验证差分得分与胜率；固定局面合法率不能证明对局策略更强。

当前测试覆盖首家不可过牌、全部牌型、花色去重、小规模独立穷举对照、公开牌池和底牌约束、隐私隔离、恶意/超长参数、搜索上限、调用次数上限、取消后不写入及关闭工具后的旧调用路径。真实网关支持、完整对局策略收益、同任务 LLM 推理耗时对照尚未实测，不能作为已取得的结论。
