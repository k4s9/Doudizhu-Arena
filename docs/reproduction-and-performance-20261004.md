## 实时链路：五观众、二十次重连和慢订阅隔离

```bash
conda run --no-capture-output -n doudizhu-arena python -I -B \
  scripts/benchmark_realtime.py --output data/realtime-benchmark-new \
  --chromium-arg=--js-flags=--jitless
```

输出目录必须尚不存在。脚本启动独立 loopback 服务和数据库，使用正式比赛执行器、事件总线、WebSocket 路由与前端 `createMatchSocket`。五个无头 Chromium 页面执行真实连接、序号过滤、断线重连和快照同步。决策由延迟 120 ms 的 mock Provider 提供，真实模型入口被禁用；不加载用户比赛配置。上面的 `jitless` 参数用于本机 ARM Chromium，应在跨机器比较时保留或明确区分。

最终运行使用采样器 v2，完成了五观众轮换的 20 次运行中重连。每次都验证断线期间遗漏了自然对局事件、恢复快照水位跨过缺口，并继续收到连续增量；最终五页完整快照与同一权威快照一致。共同收到的自然事件为 608 条，页面错误为 0。

| 测量 | 样本数 | P50 | P95 |
| --- | ---: | ---: | ---: |
| 正常阶段发布至浏览器回调 | 4,590 次事件投递 | 3.821 ms | 7.039 ms |
| 运行中断线至新快照到达 | 20 次 | 1,006.400 ms | 1,011.500 ms |
| 压力阶段自然事件投递 | 1,490 次事件投递 | 24.664 ms | 34.208 ms |
| 压力阶段人工探针投递 | 50,005 次事件投递 | 26.733 ms | 40.104 ms |

事件样本按“事件 × 接收观众”计数，不是独立实验次数。发布至回调包含 SQLite 持久化、事件循环调度、序列化、loopback WebSocket 和浏览器分发，不包含发布之前的模型等待或 Vue DOM 渲染。重连耗时包含生产客户端原有的 1 秒重连定时器。前后校时的最大估计不确定度为 1.318 ms；不据此比较亚毫秒差异。启动、校时及收尾阶段未混入正常事件统计。

慢订阅测试在单独压力阶段暂停一个真实连接的服务端 relay，再通过生产总线发布并持久化 10,001 条人工探针，真实填满默认 10,000 容量队列。验证该订阅被摘除，仅保留 `resync_required`，恢复 relay 后浏览器收到通知并以 1013 关闭；五个正常观众均完整收到全部探针，内容与 SQLite 一致。这里是受控服务端背压注入，不是慢网络吞吐量测量；没有无慢订阅的同洪峰对照，不把延迟变化单独归因于慢客户端。

资源采样只读取测试控制器及其子进程树的 `/proc` 原始计数，并按阶段区分；CPU 的 100% 表示一个逻辑核心。正常阶段后端 CPU P95 为 9.99%，RSS 最大 80.53 MiB；压力阶段 CPU P95 为 57.99%。五页 Chromium 进程树正常阶段 CPU P95 为 13.97%，RSS 合计最大 1,110.71 MiB；该 RSS 含基准样本缓存、压力测试后的保留内存及共享页面重复计算，不是网页自身的净内存。完整阶段统计见原始结果。

采样器目标间隔为 500 ms，正常阶段实际间隔 P50/P95 为 500.662/501.831 ms，单次采样开销 P50/P95 为 37.145/42.557 ms。控制器自身正常阶段 CPU P50/P95 为 9.98%/12.00%，单独列出，不计为后端 CPU，也不隐去测量开销。

这是单机、单场 mock 比赛和五个正常观众的工程测量，不代表生产容量、硬实时 SLA 或真实模型性能。基准在完成运行中一致性检查后关闭自身进程，隔离比赛保留为 `interrupted`，不将其报告为完成了 100 副终局。
