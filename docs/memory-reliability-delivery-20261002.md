## 修复范围

| 范围 | 最终行为 |
| --- | --- |
| P0 反思 | 有库、无库及流局遵守同一开关；每场独立 ID、短期记忆重置；复用模型切换无库时清理旧日志关联 |
| P0 结算 | 关闭、失败或超时总结不影响结算；结算标记、终局状态和统计同一事务提交，重复执行不重计 |
| P0 准确性 | 使用正式得分、真实角色及实际完成副数，覆盖 KO、流局、平局和加赛；修复加赛副数重复计算 |
| P1 记忆 | 当前长期记忆、历史及新版本原子保存；写失败保留原文；按比赛开始使用的版本 ID 校验，覆盖 A→B→A 冲突 |
| P1 追溯 | 记录内容哈希、上一版本、来源比赛及后续使用；牌手页可查看、对照和手工整理，旧超长文本完整归档 |
| P1 长度 | 短期最多 4,000 字符、长期最多 8,000；超长模型结果拒绝保存，旧记忆不自动截断 |
| P1 评测 | 训练恢复读取冻结 manifest；checkpoint 与任务完成原子提交；所有训练调用共用预算；固定局面及完整比赛三组对照 |
| P2 并发 | 同场重复启动拒绝；长期记忆写入牌手受唯一约束保护直到总结结束；只读经验模式可并行 |
| P2 故障 | 独立学习期限和迟到结果隔离；失败可查；锁释放有界重试，后续启动能恢复已结束任务的残留锁 |
| P2 重启 | 遗留比赛转为 interrupted，已完成牌局保留；终局结算不重算，未完成总结单独记录；恢复先于凭据加载 |
| P0 交付 | CI 预建容器挂载目录，日志与停止分开；浏览器覆盖经验编辑，部署覆盖活跃比赛重启 |

只支持一个比赛执行进程拥有同一数据库。恢复不等于从最后一步继续执行原比赛：可回看已落库数据，并开启新比赛。版本校验不代表已实现多实例调度或生产 SLA。主密钥缺失/错误时可启动查看旧比赛，需要解密的 API 明确返回 503，原凭据不变。

## 评测和验证

[固定局面协议](memory-evaluation.md)统计合法率、重试、兜底需求、token、延迟及费用；[完整比赛协议](memory-full-matches.md)增加双方积分、积分差、胜负及实际兜底，固定随机对手并交换红蓝。训练/测试种子分离，测试不更新记忆，报告可只读重放得分和调用证据。

本轮验收没有新发起真实模型调用。合成经验标记为 fixture；mock 只验证流程，不能证明真实记忆收益。真实训练、对战效果及统计结论需要冻结协议下的独立实测。

最终证据索引：[validation-summary.json](reviews/20261002-memory-reliability/validation-summary.json)。所有 Python 使用 `doudizhu-arena` conda 环境与 `-I -B`，后端测试启用断网保护。沙箱内 SDK MockTransport 挂起后中止；同样的离线门禁改在沙箱外执行，失败尝试保留在 `data/p0-p2-20261002/`。

最终完整回归 **502 passed**（645.79 秒），断网保护记录 **0** 次连接；前端 **11 passed**。固定局面 mock 的 **48 个决策、90 次调用**与完整比赛 mock 的 **6 场、12 个桌副、288 次调用**均通过只读审计，三组 mock 得分和合法性表现相同。浏览器页面异常为 0，两观众的 10 条共同事件逐条一致；最终构建、终局重启与活跃比赛重启验收均通过。

浏览器验证生产构建的报告、回放、双观众事件一致、断网后的终局恢复及记忆编辑后刷新。本机 ARM Chromium 显式使用 `--chromium-arg=--js-flags=--jitless`，CI 保留默认 Chromium；本机浏览器计时不是生产性能证据。

隔离容器使用独立端口、空密钥与独立数据库。除完成比赛重启，还用 `scripts/verify_match_recovery.py` 暂停随机牌手比赛，重启后校验中断状态、原分数/记忆、锁释放及下一场单次结算。命令已加入 `.github/workflows/ci.yml`。
