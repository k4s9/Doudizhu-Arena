# 叫分阶段设计方案

## 范围

本轮先完成对局观战页的叫分阶段。目标是让观战者在一个视区内判断当前轮次、最高叫分、轮到谁决策、每位参与者的牌力信息与闲家状态。出牌阶段、比赛配置页和后端规则不在本次范围内。

## 现有数据与展示映射

| 数据字段 | 展示位置 | 作用 |
| --- | --- | --- |
| `bidding_order` / `idle_seat` | 三个竞叫席与旁观席 | 决定本轮参与者和顺序 |
| `current_seat` | 阶段摘要和高亮席位 | 标识正在思考的代理 |
| `bidding_history` | 席位状态与完成进度 | 区分等待、已叫分和不叫 |
| `current_high_bid` / `current_high_bidder` | 阶段摘要和当前席位门槛 | 展示竞争基准 |
| `players[seat]` / `hand_cards[seat]` | 席位身份与公开手牌 | 维持观战模式的全牌可见性 |
| `thoughts[seat]` | 最近完成席位的分析区 | 呈现本次叫分的模型推理 |
| `dizhu_cards` | 标题栏右侧 | 持续保留底牌上下文 |

实时 `bidding_update` 事件中的 `seat` 是刚完成叫分的席位。前端在收到事件后以 `bidding_order` 减去 `bidding_history` 中已完成的席位，推导下一行动席，避免把刚完成的选手误标为“正在叫分”。最近完成席保留该次推理文本，供观战者核对决策依据。

## 信息层级

1. 顶部标题栏固定表达桌号、当前阶段、首家和底牌。
2. 阶段摘要把最高叫分、保持者和当前行动席放在同一条扫描路径上。
3. 三个竞叫席按首家、二家、尾家的实际顺序纵向排列。当前席位使用金色左侧标记；最近完成席显示决策依据；已完成和待叫席位保持次级视觉层级。
4. 闲家独立于竞叫序列，使用旁观席说明其不参与和手牌不公开。

## 组件边界

- `BiddingView.vue` 负责从实时快照派生叫分进度、桌面摘要和响应式布局。
- `BiddingSeat.vue` 负责单席的状态表现、公开手牌和最近完成叫分的决策文本。
- `IdleSeat.vue` 继续作为闲家身份展示；只调整了样式以纳入新的旁观区域。
- `GameTable.vue` 在叫分阶段不再额外套一层通用卡片，避免出现嵌套视觉容器；其他阶段保持原样。

## 交互状态

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| 等待 | 未出现在 `bidding_history` 且不是 `current_seat` | 低对比度状态与正常手牌 |
| 思考中 | `seat === current_seat` | 金色左缘、活动标记和当前门槛 |
| 已叫分 | 历史值大于 0 | 绿色结果标签；最高叫分者额外标记 |
| 不叫 | 历史值为 0 | 中性结果标签和降低的手牌对比度 |
| 最近分析 | 最新历史席位存在推理文本 | 在该席下显示本次叫分的决策依据 |
| 旁观 | `seat === idle_seat` | 单独的旁观区，不显示手牌 |

## 响应式约束

- 宽屏：竞叫席与旁观席保持两栏，摘要保持三项并列。
- 小于 640px：摘要折为两行，旁观席移到竞叫席下方；牌组可自然换行，文字不覆盖状态标签。
- 动效仅用于当前席位的状态点，并遵守 `prefers-reduced-motion`。

## 验收标准

- 历史叫分、当前最高叫分和当前席位变化时，不需后端转换即可同步反映在页面上。
- A/B 桌同时进入叫分阶段时，各自的数据和思考文本不会串桌。
- 在桌面和窄屏下，玩家名称、状态、手牌和闲家说明均可读且不重叠。
