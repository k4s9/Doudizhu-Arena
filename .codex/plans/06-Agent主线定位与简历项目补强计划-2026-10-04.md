**C：构建小而清楚的留出实验**

当前 exporter 只取 rule_feedback 来源、每 seed 排序后的前若干决策，默认 8 条，代码已注明是 engineering fixture。应修正偏向叫分/早期状态的取样，并避免仅从待比较方案自己的轨迹抽样。

建议先用已有 42 份失败/恢复文件做开发回归集；未用于改 Prompt 的来源再作为留出评测。可从冻结的规则策略或预先固定的轨迹生成观察，清楚声明来源与支持范围。按来源 seed 与 match 隔离开发和测试，检查只有当前玩家合法可见的信息，不能含对手手牌、未来动作或未来总结。

一个探索性起点：**12 个未用于开发的测试 seed，每 seed 6 条局面，共 72 条**，叫分、领出、跟牌各取 2 条；对无法满足类别的 seed 预先规定处理方式，不能看模型输出后挑选。复杂飞机、边界牌型、接近终局另设压力集，结果独立报告。人工复核一小批合法性与可见性样例，因为数据生成和评测复用规则引擎，不能用同一实现的自洽代替所有正确性验证。

三协议每局面最多 1+3+3=7 次调用，因此 72 条局面每模型最多 504 次，两模型最多 **1,008 次正式调用**，不含开发、压力集和重复实验。实际费用先按输入/输出上限及冻结单价预检；不沿用历史免费账户假设。

| 指标层次 | 应报告什么 |
| --- | --- |
| 首次调用 | 可用率、返回后合法率，以及包含接口失败的首次决策成功率 |
| 决策结束 | 模型最终合法率、非法输出恢复率、provider 错误恢复率；固定观察无系统出牌兜底 |
| 代价 | 每决策调用次数、已知输入/输出 token、usage 覆盖率、费用、端到端延迟 P50/P95 |
| 对照 | 通用重试与规则反馈在同一 seed/局面上的结果差值，保留胜/平/负与失败类别 |
| 不确定性 | 以 seed 为独立统计簇，给 seed 级分布和适当区间；12 seeds 仅是起点，不保证显著性 |

先冻结规模、协议和主要指标，再看结果；需要扩大时依据预先约定的精度/成本要求，不能只为得到显著提升持续追加样本。若没有提升，分析何类错误可恢复、代价是否更高，也可以形成有价值的工程结论。

随后用少量新的完整双桌对局确认执行兼容性即可；完整对局与固定观察分别报告，不能混用分母或将动作合法率当胜率。

**D：只补能检验真实边界的故障测试**

已有预算、慢队列、事件水位、取消迟到结果、事务回滚和整任务恢复测试。新增重点是穿过实际执行路径，而非重复函数行为。

| 场景 | 建议验收 |
| --- | --- |
| 实际出牌途中 thought/decision 写入失败 | 动作与结果不部分落库，不广播成功事件；内存可能已变更时，执行器显式失败停止，不能继续输出“完整运行”报告 |
| 隔离运行进程在任务中途被终止 | 重启后按租约恢复，旧 attempt 标 interrupted，已完成 task 不重跑，未完成 task 新建 attempt，保留历史并完成最终审计 |
| 取消后迟到返回、unknown usage | 复用已有测试并在真实执行包装器复验；迟到结果无有效写入，未知费用/用量保留占额和未知状态 |

第一项当前测试主要验证 SAVEPOINT 回滚；第二项现有恢复测试主要手动构造遗留 running 记录。真实进程故障应使用独立测试进程、隔离数据库和 mock，不中断用户正在使用的服务。恢复目标仍是整任务重跑，不扩展到任意出牌位置续跑。

**E：目标岗位需要工具开发证据时，做一个小的主动工具回路**

当前 Provider 返回字符串，模型请求不带 tools；规则校验由服务端在生成后执行。可以新增一个独立 ToolAgent，先接一个实际确认支持原生工具调用的模型端点，只开放 `validate_action(action)`。

工具由服务端绑定当前 seat、decision 和可见观察，返回 `valid/error_code/message`，不提交出牌，不允许模型指定其他玩家或任意历史状态。模型先提出或检查候选，再提交明确 final action，最终仍走现有规则校验与动作提交入口。建议每决策最多 2 次工具查询、3 次模型调用，所有模型调用和工具结果都进入记录及上下文预算。

需要同时补的测试：未知工具名、错误类型/额外参数、过期上下文、重复请求或超过工具上限、取消后的工具返回、工具前后游戏状态哈希不变、输出不含对手隐藏信息。只有这些边界落实，才适合写“受限工具执行与反馈闭环”。

评测用同一留出局面比较工具组和 3 次调用的规则反馈组，分别报告合法率、工具使用率、成本与延迟。工具描述会增加上下文，不能声称与原协议信息量完全相同；这是一套执行方案的对照。结果没有改善也应保留。

完整 `get_legal_actions` 暂后置：当前 RandomAgent 的候选生成不覆盖全部复杂牌型，不能直接改名作为完整合法动作集合。若以后实现枚举，需覆盖所有牌型，在小手牌上用穷举子集检查合法性与完整性；部分候选应明确标为建议或截断。合法候选选择提高合规性，也不自动证明竞技策略更强。

**F：两个投入较小的展示/测量选项**

- 失败详情目前跳转到整场回放。增加 decision_id → 桌/手/动作序号的定位，打开时跳到对应动作并显示校验和最终动作。验收叫分与出牌、双桌、兜底/托管记录都不会跳错；按权威序号而非时间戳猜测位置。
- 基于现有浏览器验收，建议固定 mock，测试 5 个观众、20 次运行中断线恢复和 1 个慢客户端。验证正常观众状态一致、重连状态收敛、慢客户端不阻塞正常观众；记录硬件、P50/P95 恢复时间、正常观众延迟及 CPU/内存。该规模只用于小型工程验证，不写高并发能力；模型等待时间与事件传输时间分开。

**可以结束这一轮开发的标准**

- 当前同一版本的测试、构建、演示通过，有失败和跳过范围说明。
- 若主投 Agent：有一套真实固定观察留出实验、可复查的逐次输出与成本/延迟分析，结果可以是没有提升。
